# 校园智能服务台与知识运营后台介绍

## 一、项目背景
高校信息通常分散在教务处、学生工作处、学院通知、附件文件和各类公告页面中。学生在查询奖学金、转专业、课程认定、补退选、宿舍服务等信息时，往往需要多次搜索和比对，信息获取成本较高。

本项目围绕“校园服务智能化”这一目标，构建学生侧校园智能服务台和运营侧知识运营后台。用户可以通过自然语言提出事项，系统结合校园知识库和已审核社区知识生成结构化回答并提供来源；知识运营人员负责内容治理、知识发布和检索运行，持续提升信息获取效率和可信度。

## 二、项目目标
本项目的目标包括：

- 提供统一的校园信息问答入口
- 利用 RAG 技术提升问答准确性和可追溯性
- 通过数字人与语音提供可选讲解体验
- 构建校园社区，让经验型知识能够沉淀和复用
- 建立知识运营审核与发布流程，保证知识质量

## 三、系统定位
本系统不是通用聊天机器人，而是面向高校场景的垂直智能服务平台。它更关注：

- 校园问答的准确性
- 信息来源的真实性
- 交互流程的完整性
- 社区知识与官方知识的边界管理

## 四、核心功能说明
### 1. 校园智能服务台
用户可以直接输入自然语言问题，例如：

- 转专业后课程补退选怎么操作
- 奖学金材料需要准备什么
- 宿舍报修在哪里提交

系统会基于：
- 官方知识库
- 社区知识条目
- 大模型生成能力

输出结构化回答，并尽量附上来源信息。

### 2. RAG 检索增强
系统在大模型生成前会先进行知识检索。当前知识来源主要包括：

- 学校通知知识库
- 结构化附件索引
- 审核通过的社区知识条目

检索命中后，相关内容会作为上下文拼接到模型输入中，从而提升回答贴合度。

### 3. 数字人展示
服务台采用数字人导办布局，支持：

- 首次进入播放欢迎视频
- 问答阶段切换到讲解视频
- 后端 TTS 播报
- 欢迎、待机、讲解三种状态切换

### 4. 校园社区
校园社区支持：

- 发布帖子
- 回复帖子
- 浏览帖子详情
- 展示已审核内容

社区内容不会直接进入主知识库，而是经过筛选、审核和知识生成后，才可作为辅助知识来源使用。

### 5. 知识运营后台
知识运营后台支持：

- 审核帖子
- 审核回复
- 审核社区知识
- 查看候选帖子
- 生成社区知识条目

知识运营员优先处理系统筛选后的高价值内容，从而减少人工工作量。

### 6. 登录注册
用户认证体系支持：

- 普通用户邮箱验证码注册
- 邮箱作为普通用户唯一标识
- 管理员账号密码登录
- 注册通知邮件发送

## 六、系统业务闭环
本项目目前已经形成了完整的业务闭环：

1. 用户登录系统
2. 用户在首页提问
3. 系统检索知识库并生成回答
4. 数字人展示讲解内容
5. 用户可查看来源信息
6. 学生可在社区补充经验内容
7. 知识运营员审核优质帖子与回复
8. 社区知识生成并进入审核流程
9. 审核通过后的社区知识反哺问答系统

## 七、项目亮点
### 1. 知识可追溯
回答不仅提供结果，还尽量附带来源依据，降低“黑盒回答”风险。

### 2. 社区与问答联动
校园社区不只是互动模块，还可作为辅助知识沉淀来源，为问答系统提供经验型补充。

### 3. 数字人交互体验
首页采用数字人展示方式，提升项目展示感和交互效果。

### 4. 角色化知识运营
知识运营员具备审核、筛选、知识发布和检索运行维护能力，保证系统内容质量。

### 5. 可持续质量闭环
系统用自动测试、RAG 金标和服务旅程覆盖核心链路，为长期试运营和持续发布提供基础。

## 八、适用场景
- 校园办事导办与政策问答
- 教务、学生工作和生活服务咨询入口
- 校园知识运营与内容治理
- 智能体、RAG 与数字人综合应用

## 九、后续可拓展方向
后续可以继续扩展：

- 更精细的知识库治理
- 社区知识质量评分机制
- 更自然的数字人口播与动作联动
- 小程序与移动端适配
- 更细粒度的权限体系
- 更强的知识统计与运营分析能力

## 十、总结
校园智能服务台与知识运营后台围绕“事项问答 + 来源追溯 + 社区知识沉淀 + 人工发布”的整体思路，实现了完整的校园知识服务闭环。大模型负责理解与表达，检索和人工审核负责可信边界，数字人负责可选讲解体验。
