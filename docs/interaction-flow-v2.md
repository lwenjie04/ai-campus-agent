# 数智校答 V2 交互与跳转说明

日期：2026-10-20  
设计版本：银白背景 + 深绿色强调色  
设计文件：https://www.figma.com/design/AanmCyrCvXPqzdrzTIlIJu?node-id=10-94

本文是下一版的交互规格。标记“已有”的能力来自当前仓库；“新增”或“调整”表示后续实现工作。Figma 当前只有首页进入示例对话、对话返回首页等基础跳转，不能视为完整功能已经接通。

## 1. 全局规则

1. 页面之间用路由跳转；登录、搜索、历史、来源、设置等辅助操作使用弹窗或抽屉。
2. 分类卡进入事项列表，推荐问题写入输入框；只有“发送”和非中文输入法组合期间的 Enter 提交问题。Shift+Enter 换行。
3. 开始提问不等于发送问题，也不扣游客试问额度。
4. 一次成功的游客试问后，再提交问题时要求登录；额度以服务端为准，新建对话不重置额度。失败请求沿用服务端回退规则。
5. 登录成功后回到触发登录的操作，不统一跳首页或后台；取消登录保留草稿，不执行操作。
6. 浏览器返回、刷新、关闭抽屉后应有明确落点；页面切换不得丢失草稿或删除历史。
7. 来源和播放状态归属具体回答；切换回答、会话或页面时停止旧音频，来源不得串到别的消息。
8. 产品文案使用功能名和实际状态，不使用宣传口号。

## 2. 页面与建议路由（均为前端路由）

当前 App.vue 使用 activeSection / communityView 切换组件，尚未接入以下 URL 路由。下表是建议的目标结构，不是已有接口。

| 页面 | 建议路由 | 访问 |
| --- | --- | --- |
| 首页 | / | 所有人 |
| 问答入口 | /chat | 恢复当前可访问的对话；没有则转 /chat/new |
| 新对话 | /chat/new | 所有人；首次发送前不创建空历史 |
| 对话详情 | /chat/:conversationId | 当前浏览器及当前身份有权访问的会话 |

| 事项详情 | /services/:serviceId | 所有人 |

事项详情先整理事项用途、推荐问题和可核对入口；具体政策优先从来源获得，避免复制一份长期不更新的办理条件。

## 4. 对话页的所有主要动作

| 控件 / 事件 | 操作逻辑 | 状态与异常 | 当前情况 |
| --- | --- | --- | --- |
| 输入框 | 保存当前会话草稿；支持中文输入法、换行 | 空白内容不可发送 | 基础输入已有；草稿和组合输入需完善 |
| 发送 / Enter | 校验内容 → 检查身份、额度 → 添加用户消息与回答占位 → 流式生成 | 同一会话不可重复发送同一请求 | 流式链路已有 |
| 流式生成中 | 显示“正在检索 / 正在生成”，逐段更新当前消息 | 不伪造检索步骤；只能显示真实收到的状态 | 已有占位与增量，阶段状态需补协议 |
| 停止生成 | 中止当前请求，保留已生成文本，标注“已停止” | 与停止朗读是两个动作；额度按服务端结果处理 | 新增取消协议与消息状态 |
| 继续追问 | 同一 conversationId 内提交，携带该会话上下文 | 不混入其他会话消息 | 单会话上下文已有 |
| 推荐追问 / “需要准备什么材料” | 预填输入框并聚焦 | 用户可修改，再发送 | 新增 |
| “帮我找最新通知” | 预填带当前事项和适用学年的问题 | 仍查询现有知识；找不到新通知明确说明，不能声称实时联网查到 | 新增交互；沿用现有检索边界 |
| 新建对话 | 保存旧会话，停旧音频；打开空对话 | 不删除旧历史，不重置游客额度；有生成时先中止再切换 | 当前 resetSession 清空会话，不等价于新增会话 |
| 历史对话 | 桌面抽屉 / 手机侧栏列出当前身份的历史 | 点击恢复消息；空列表显示“暂无历史对话” | 新增多会话列表 |
| 复制 | 复制该条完整回答正文 | 成功提示“已复制”；失败提供可选中文本 | 新增 |
| 有帮助 | 记录当前回答的反馈；每条消息每个身份可切换一次当前选择 | 写入成功才显示“已记录”；失败回退并允许重试 | 新增反馈存储和接口 |
| 朗读图标 | 播放当前选中回答；再次点击停止 | 生成中可等待完成后播放；不与另一条音频叠加 | 已有 TTS，逐条按需控制新增 |
| “开启语音讲解” | 选中当前回答，展开讲解面板并播放 | 游客需要登录时先登录；没有回答时不调用 TTS | 新版需接线 |
| 切换会话 / 离开问答页 | 保存草稿和生成结果，终止该会话尚未结束的请求，停止播放 | 避免旧请求回写到新会话 | 新增多会话隔离及取消处理 |
| 重新打开对话 | 恢复已保存消息和草稿，不自动重新请求模型或播放语音 | 生成中刷新留下的内容标记“已中断，可重试” | 已有单会话缓存；中断状态新增 |
| 回复失败后的重试 | 原问题关联同一失败位置，发起一次新请求 | 不再次追加相同用户气泡；重试前继续检查身份和额度 | 新增明确重试动作 |

### 来源操作

| 控件 | 行为 |
| --- | --- |
| 桌面“来源” | 展开 / 收起参考来源栏，展示选中回答的资料 |
| 手机“查看 N 份官方来源” | 打开底部来源抽屉，不挤掉输入框；关闭回当前回答 |

| 附件 | 打开 / 下载原始文件，明确标注文件类型 |

| 无匹配来源 | 显示“暂无可核对来源”，保留无法确认的说明，不显示虚假“官方来源”标签 |

后端已经返回来源标题、URL、摘要、附件和社区帖子 ID。正式的发布日期、适用学年和有效性元数据尚需补齐；设计稿中的 2025 年示例不等于已有通用时效校验。

## 5. 登录、注册与游客额度

### 提问触发登录

1. 游客第一次成功提问后记录已使用体验；再次提交时保留问题、conversationId 和操作意图。
2. 弹登录；关闭弹窗留在原页面，草稿仍在。
3. 同页完成登录后，只恢复一次刚刚明确提交的操作。
4. 如果刷新或隔天恢复了草稿，先展示“继续提问 / 放弃”，不直接重新发送。沿用现有 24 小时待问恢复窗口。
5. 请求失败保留待问，不在登录状态变化、组件重挂载时重复发送。

当前代码已有游客一次试问、同页登录续问及刷新后确认恢复。社区来源入口尚需和主导航统一执行登录检查。

### 其他登录动作

| 操作 | 成功 | 失败 / 取消 |
| --- | --- | --- |
| 主动登录 | 关闭弹窗，保持原页面 | 留在表单并显示原因 |
| 社区入口触发登录 | 进入原社区页面或原帖 | 回原页面 |
| 管理员从问答页登录 | 仍留在问答页；账号菜单出现知识运营入口 | 不因为管理员身份强制跳后台 |
| 发送注册验证码 | 显示倒计时，允许到期后重发 | 保留邮箱，不产生假成功 |
| 注册提交 | 按当前实现切回登录表单，填入注册邮箱；待执行操作继续保留 | 保留已填资料，错误定位到对应字段 |
| 会话过期 | 保存当前草稿；需要权限的动作重新登录 | 不丢失已显示的回答 |
| 退出登录 | 停音频、终止请求，清理当前账号界面并回首页 | 不把上个账号会话展示给游客或另一账号 |
| 切换账号 | 执行退出再登录；显式完成后切到新账号空间 | 不把简单返回首页当作身份切换 |

语音沿用服务端鉴权。若游客无 TTS 访问权限，登录成功后恢复的是“播放这条回答”，不是再发送一遍问题。

## 7. 管理员后台

管理员入口仅向管理员展示，直接访问后台路由也必须通过服务端鉴权；前端隐藏按钮不是权限检查。

| 操作 | 结果 |
| --- | --- |
| 知识运营 / 检索运行 | 切换后台子页面，保留所在列表 |
| 待审核帖子 / 回复“查看详情” | 原页详情弹窗；关闭回原列表 |
| 通过帖子 / 回复 | 服务端确认后从待审核队列移除并刷新统计 |
| 拒绝帖子 / 回复 | 确认后调用拒绝接口；失败保持原状态 |
| 候选帖子“生成知识草稿” | 生成待审核知识，不直接发布进 RAG |
| “通过并生成知识” | 分别执行通过、生成；若第二步失败，明确提示“帖子已通过，草稿生成失败”，只重试生成 |
| 知识草稿“查看来源” | 打开对应原帖详情，不丢失审核位置 |
| 知识“通过并发布” | 服务端成功后更新状态，只有已批准内容参与检索 |
| 知识“拒绝” | 二次确认后拒绝；失败保持列表项 |
| 刷新列表 / 状态 | 原位置重新拉取，不整页跳走；失败显示错误 |
| LightRAG 控制台 / API 文档 | 仅在已配置可访问地址时新标签打开；没配置则禁用 |
| 普通用户访问后台 | 显示权限不足并提供返回入口；不通过前端身份修改放行 |

审核、生成和检索状态查询已有接口；路由、拒绝确认、准确的部分成功提示及后台细节页面需按新版整理。

## 9. 需要补的工程能力

| 能力 | 现状 | 下一版所需 |
| --- | --- | --- |
| 页面路由 | App.vue 用局部状态切页，依赖中无 vue-router | 页面 URL、返回落点、权限守卫、404、部署回退 |
| 多会话历史 | 全局单会话 localStorage 缓存 | 同浏览器多会话、账号隔离、标题、更新时间；跨设备同步不在本版承诺内 |
| 新对话 | resetSession 覆盖当前消息 | 保存旧会话后创建新会话，首次发送才落历史 |
| 请求中止 | fetch 未接 AbortSignal | 可取消流式请求、按会话隔离回写、中断状态 |
| 语音 | 当前随生成按句触发 | 默认不自动播放，用户按需开启；播放状态绑定 messageId |
| 反馈 | 设计稿有“有帮助”，未发现对应接口 | 与回答及 requestId 关联的反馈记录 |
| 办事指南 | 没有独立目录与事项页 | 四类事项清单、关键词、可核对来源和提问模板 |
| 来源时效 | MessageSource 没有正式发布日期/适用学年字段 | 返回并展示可信元数据，未知值不推断为已过期 |

建议状态至少区分：ready、generating、done、error、interrupted；语音另有 off、loading、playing、error。不要用一个 loading 同时表示登录、发送、检索、语音和审核。
